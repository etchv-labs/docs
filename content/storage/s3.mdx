Connect a general-purpose S3 bucket with a cross-account IAM role. Etchv uses temporary credentials; no AWS access key is needed.

## Create a limited role

Name the role with the prefix `etchv-storage-`, such as `etchv-storage-production`. Grant access only to your destination prefix:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:PutObject", "s3:GetObject"],
    "Resource": "arn:aws:s3:::YOUR_BUCKET/etchv/*"
  }]
}
```

Replace the bucket and prefix. `DeleteObject`, `ListBucket` and ACL permissions are unnecessary. For customer-managed KMS encryption, also grant `kms:GenerateDataKey` and `kms:Decrypt`, with access in the key policy.

## Add the destination

Use [Dashboard storage](/dashboard/storage) or an owner/admin key with `storage:write`:

```sh
curl -X POST https://api.etchv.com/storage/destinations \
  -H "X-API-Key: $ETCHV_API_KEY" -H 'Content-Type: application/json' \
  -d '{"name":"Production S3","provider":"s3","bucket":"YOUR_BUCKET",
       "region":"us-east-1","prefix":"etchv","visibility":"private",
       "role_arn":"arn:aws:iam::YOUR_ACCOUNT_ID:role/etchv-storage-production"}'
```

The response returns `id`, `aws_principal_arn` and a unique `external_id`. Put the exact returned values in your role’s trust policy:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"AWS": "RETURNED_AWS_PRINCIPAL_ARN"},
    "Action": "sts:AssumeRole",
    "Condition": {"StringEquals": {"sts:ExternalId": "RETURNED_EXTERNAL_ID"}}
  }]
}
```

Keep the exact external ID condition. It prevents other customers from using your connection. See [AWS third-party role access](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_common-scenarios_third-party.html).

## Test and use

1. Click **Test connection**, or `POST /storage/destinations/{id}/verify`. Etchv writes and reads a probe under your prefix.
2. Fix any trust or permission error, then verify again.
3. Pass the destination ID in your [embedding request](/docs/storage#select-storage-on-a-request).

| Visibility | Configuration |
| --- | --- |
| Private | Keep S3 Block Public Access enabled |
| Already public | Set `visibility: "public"` to include direct URLs |

Etchv honors default encryption and never changes bucket policy or ACLs. [Conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) protect existing objects; retries verify their bytes before accepting them.

<Details title="Supported S3 configurations">
Commercial AWS regions and official S3 endpoints are supported. S3 Express directory buckets, access-point ARNs, custom S3-compatible endpoints and per-request bucket overrides are not. Create a separate destination for another bucket.
</Details>
