## Request

Send multipart form data with an API key scoped to `watermarks:embed`.

```sh
curl --fail-with-body https://api.etchv.com/watermarks/images \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -H "Idempotency-Key: campaign-01-partner-42" \
  -F 'file=@photo.jpg' \
  --form-string 'data={"delivery":"partner-42-preview"}' \
  -D response-headers.txt \
  --output response-body
```

Check the status in `response-headers.txt` before saving the body as an image.
The [SDKs](/docs/sdks/node) handle pending jobs automatically.

| Form field | Value |
| --- | --- |
| `file` · required | Encoded image bytes. Maximum 50 MB and 40 MP across all frames/pages |
| `data` · required | A non-empty JSON object, sent as a string. Use a reference to your delivery record |

Let your HTTP client set the multipart boundary.

## Request options

| Option | Use it for |
| --- | --- |
| `Idempotency-Key` header | Safe retries. Use 8–128 letters, digits, hyphens or underscores; keep the same key and input for a retry |
| `accelerator` query | `cpu` by default; `gpu` on Business/Enterprise costs 3× credits when GPU runs. [GPU guide](/docs/api/gpu) |
| `storage_destination_id` query | Send the result to a verified customer bucket. Omit for included Etchv storage |
| `storage_key` query | Optional URL-encoded filename under that destination’s prefix. [Storage guide](/docs/storage) |
| `webhook_id` query | Send completion events to one enabled endpoint. **Async only**. [Webhooks](/docs/api/webhooks) |

## Choose sync or async

| Endpoint | Response |
| --- | --- |
| `POST /watermarks/images` | Waits up to 20 seconds: `200` file or `202` job receipt |
| `POST /watermarks/images/async` | `202` receipt after validation and durable acceptance |

For `202`, follow `result_url` with your API key and respect `Retry-After`.
[Full job workflow](/docs/api/async#retrieve-a-pending-result-either-mode).

## Response

**`200` contains the verified image.** Save its bytes directly using the filename
in `Content-Disposition`. **`202` contains JSON**, not a finished file.

| Header | Keep it for |
| --- | --- |
| `X-Watermark-ID` | Looking up your record; a 64-character SHA-256 digest |
| `X-Asset-ID`, `X-Source-Asset-ID` | Finding the output and original in the [asset library](/docs/api/assets) |
| `X-Request-ID` | Recovery and support |
| `Content-Type`, `Content-Disposition` | Native MIME type and suggested filename |
| `X-Etchv-Accelerator` | Whether CPU or GPU ran |
| `X-Storage-Delivery-ID` | Tracking delivery when you selected customer storage |

<Callout title="Keep the record behind the ID">
  Etchv hashes your JSON after sorting keys and removing insignificant whitespace.
  Identical canonical data gives the same ID. Detection returns that ID, not the
  original JSON. Store the ID alongside your record.
</Callout>

## Native format preservation

| Format | What stays |
| --- | --- |
| JPEG/JPG, PNG, BMP, PPM, WebP | Original container and dimensions |
| APNG, GIF, animated WebP | Visible frames, timing and loop count |
| TIFF | Every page |
| PSD / PSB | Original layers plus two editable watermark layers |

File signatures determine the format. High-bit-depth and CMYK inputs are rejected.
[Frame, page and layer limits](/docs/api/errors#image-limits).

<Details title="Encoding, color and transparency">

- JPEG: quality 100, 4:4:4 chroma. WebP: lossless. TIFF: lossless Deflate.
- Palette and grayscale inputs may expand to RGB. GIF frames must be at most 1 MP.
- RGB ICC profiles, EXIF and resolution are preserved where supported; other metadata is not guaranteed.
- RGBA transparency is preserved. Verification composites onto white; fully transparent frames cannot carry a watermark.
- Encoding settings and file bytes may change. Final visible-image quality must be at least 35 dB PSNR, including encoding loss.

</Details>

<Details title="Photoshop file requirements">

Use 8-bit RGB PSD/PSB files with an opaque, faithfully renderable composite and a
stored merged preview. Unsupported effects are rejected rather than flattened.
Keep both added watermark layers visible; editing or removing them can affect recovery.

</Details>

<Details id="output-verification" title="How Etchv verifies the delivered file">

Etchv decodes the final serialized output and checks the exact ID in every
frame, TIFF page or layered composite. Dimensions must remain unchanged.
A file that fails verification returns `422`; failed jobs refund reserved credits.

</Details>
