## Request

Use `watermarks:embed`, a PDF and a non-empty JSON reference object.

```sh
curl --fail-with-body https://api.etchv.com/watermarks/documents \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -H "Idempotency-Key: investor-preview-42" \
  -F 'file=@presentation.pdf' \
  --form-string 'data={"delivery":"investor-preview-42"}' \
  -D response-headers.txt --output response-body
```

`200` returns the native PDF; `202` returns a job receipt. Check the status before
saving the body as a PDF. Save `X-Watermark-ID` with your record.
[Response headers and request options](/docs/api/embed#request-options).

## Choose sync or async

| Operation | Endpoint |
| --- | --- |
| Embed | `POST /watermarks/documents` |
| Detect | `POST /watermarks/documents/detect` with `file` and `watermarks:detect` |

Async supports `webhook_id`. Both modes support `accelerator=gpu` on Business/Enterprise;
embedding also supports `storage_destination_id` and `storage_key`.

## <span id="first-supported-profile" />Supported files

| Requirement | Limit |
| --- | --- |
| Document | Passive, unencrypted PDF; 1–8 unrotated pages with standard page units |
| Upload / output / detection | 20 MB / 64 MB / 64 MB |
| Rendered pixels at 144 dpi | 4 MP per page; 16.8 MP total, enough for eight A4 or US Letter pages |
| Page content | Text, vectors, scanned images or a mixture |
| Unsupported | Forms, digital signatures, active content and annotation types not listed below |

Text stays searchable and selectable. Fonts, vectors, page sizes, supported
annotations and document metadata remain. Watermark textures can increase file
size; editing the layout or removing those textures can affect recovery.

<Details title="Annotations, attachments and active content">

- **Retained:** links, text notes, popups and static `PlyBorder` annotations, including relationships and appearance streams. Borders need a normal Form appearance; actions on notes, popups and borders are unsupported.
- **JSON attachments:** retained byte-for-byte, not watermarked. Require a `.json` name, `application/json` type and valid UTF-8 JSON object/array. Maximum 64 nesting levels, 64 KB each, 256 KB total and 16 files.
- **Removed:** document/page open actions, additional actions and document-level JavaScript that run automatically.
- **Rejected:** other active content (including scripts on links), non-JSON attachments, forms and digital signatures. Scanned handwritten signatures are ordinary page content.

Annotations are retained separately and do not receive their own watermark.

</Details>

<Details title="Rendering and verification">

Each final page must recover the exact ID and meet 35 dB PSNR. Etchv checks two
rendering engines using a canonical 144 dpi RGB rendering with annotations hidden.
Two blend textures carry the mark; pages are not flattened.

Embed fonts in source PDFs for consistent rendering. Etchv does not add fonts to
your PDF: its verification render uses standard substitutes, and other viewers
may choose different ones. Printing,
re-saving and edits can affect recovery.

</Details>

## Billing and results

- **Embed:** one CPU credit per page, so an eight-page PDF costs 8; failures refund the reservation.
- **Detect:** one CPU credit per PDF, whatever its page count. `units` reports each page; the top-level ID is present only when all pages recover the same ID.
- **Retrieve:** [job results](/docs/api/async) last 24 hours. Same-key retries return saved bytes without another charge.

## SDKs

| SDK | Embed / detect |
| --- | --- |
| [Python](/docs/sdks/python) | `embed_document` / `detect_document` |
| [Node.js](/docs/sdks/node) | `embedDocument` / `detectDocument` |

In these SDKs, `image` contains native PDF bytes. Save using the returned filename
and `application/pdf` content type. The [other SDKs](/docs#choose-your-integration)
also support PDFs. DOCX and PPTX are not yet supported.
