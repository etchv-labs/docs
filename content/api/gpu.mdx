Request GPU processing for any embedding or detection endpoint on Business or Enterprise. The output format, watermark ID and verification are the same as CPU processing.

## Request GPU processing

Add `accelerator=gpu` to a sync or async request. Use `accelerator=cpu` to request CPU explicitly.

```sh
curl --fail-with-body "https://api.etchv.com/watermarks/videos/async?accelerator=gpu" \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -H "Idempotency-Key: launch-video-partner-42" \
  -F 'file=@launch.mp4' \
  -F 'data={"asset":"launch-video","recipient":"partner-42"}'
```

| SDK | Option |
| --- | --- |
| [Python](/docs/sdks/python) | `accelerator="gpu"` |
| [Node.js](/docs/sdks/node) | `{ accelerator: 'gpu' }` |
| [Go](/docs/sdks/go) | `etchv.Options{Accelerator: etchv.AcceleratorGPU}` |
| [Rust](/docs/sdks/rust) | `Options::new().accelerator(Accelerator::Gpu)` |
| [C#](/docs/sdks/csharp) | `new RequestOptions(Accelerator: Accelerator.Gpu)` |
| [Java](/docs/sdks/java) | `options.withAccelerator(EtchvClient.Accelerator.GPU)` |

The dashboard, [MCP](/docs/mcp) and [automation integrations](/docs/integrations) offer the same choice. Gains vary by file: decoding and encoding still use CPU. See [performance benchmarks](https://benchmarks.etchv.com/performance).

## Credits and fallback

Etchv reserves 3× the normal credits. If processing falls back to CPU, it charges the normal amount and releases the difference. Failed operations release the full reservation.

## GPU readiness

An active Business or Enterprise workspace keeps GPU capacity warm. Additional capacity can take a few minutes to start; requests run on CPU while it starts.

### Check readiness

```sh
curl --fail-with-body "https://api.etchv.com/accelerators/gpu" \
  -H "X-API-Key: $ETCHV_API_KEY"
```

| Status | Meaning |
| --- | --- |
| `ready` | A GPU is running |
| `starting` | Starting; requests use CPU meanwhile |
| `idle` | No GPU is running |
| `unavailable` | GPU processing is unavailable |

Checking does not start a GPU. Use a key with `watermarks:embed` or `watermarks:detect`.

### Start the GPU

```sh
curl --fail-with-body -X POST "https://api.etchv.com/accelerators/gpu/wake" \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"webhook_id":"wh_0123456789abcdef0123456789abcdef"}'
```

Waking uses no credits and requires Business or Enterprise. It keeps capacity warm for 15 minutes after readiness; ongoing GPU work keeps it active. Waking again extends that window.

The optional `webhook_id` receives [`accelerator.ready`](/docs/api/webhooks#events), immediately if already ready. Otherwise poll readiness. Both endpoints return `accelerator`, `status`, `warm_until` and `ready_at`.

## See which accelerator ran

| Response | Field |
| --- | --- |
| Sync result or result download | `X-Etchv-Accelerator`: `cpu` or `gpu` |
| Receipt, job status or webhook | `accelerator_requested` and actual `accelerator` (`null` before processing) |
| Completed job | `credits`: actual charge |

The [Usage dashboard](/dashboard/history) also shows the accelerator.

## Errors

| Status | Reason |
| --- | --- |
| `403` | Plan does not include GPU |
| `404` | Webhook is missing or disabled |
| `503` | GPU service unavailable; retry later or request CPU |
| `409` | Same idempotency key used with a different accelerator |
| `422` | Accelerator must be `cpu` or `gpu` |

GPU requests share your plan’s [rate limits](/docs/api/errors#rate-limits).
