## Request

Use `watermarks:embed`, a supported MP4/MOV and a non-empty JSON reference object.

```sh
curl --fail-with-body https://api.etchv.com/watermarks/videos/async \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -H "Idempotency-Key: campaign-preview-42" \
  -F 'file=@preview.mp4' \
  --form-string 'data={"delivery":"campaign-preview-42"}'
```

This returns a `202` receipt. [Collect the result](/docs/api/async#retrieve-a-pending-result-either-mode)
with the same organization’s key. The finished file keeps its container,
frame timing and supported audio; audio is not watermarked.

## Choose sync or async

| Operation | Endpoint |
| --- | --- |
| Embed | `POST /watermarks/videos` |
| Detect | `POST /watermarks/videos/detect` with `file` and `watermarks:detect` |
| Background embed / detect | Append `/async` to either endpoint |

Sync waits briefly and returns `202` if work continues. Both operations use durable
jobs. Optional queries: `accelerator=gpu` on Business/Enterprise; `webhook_id` for
async; `storage_destination_id` and `storage_key` for embedding.
[All options](/docs/api/embed#request-options).

## <span id="first-supported-profile" />Supported files

All limits apply together: for example, the 240-frame cap allows 10 seconds at 24 fps.

| Requirement | Limit |
| --- | --- |
| Container / codec | MP4 or MOV; one progressive 8-bit H.264 track, YUV 4:2:0 |
| Timing | Constant 1–60 fps, starts at zero; no rotation |
| Duration / frames | 120 seconds / 240 frames |
| Dimensions | Even dimensions, square pixels; 1 MP per frame, 40 MP total |
| Upload / output / detection | 20 MB / 100 MB / 95 MB |
| Audio | None, or one synchronized mono/stereo AAC-LC track |

HDR, variable frame rates, fragmented MP4, other codecs, extra tracks, subtitles
and attachments are unsupported.

<Callout title="Check playback compatibility">
  Native output uses lossless H.264 with the High 4:4:4 Predictive coding profile
  and YUV 4:2:0 pixels. Use a compatible decoder; browser and hardware playback
  varies. Lossless output can be larger than the source.
</Callout>

<Details title="What verification checks">

Every frame of the final encoded video must recover the exact ID and meet 35 dB
PSNR, accounting for chroma conversion. Audio packets and timing are copied and
verified. Container metadata is copied where supported, not byte-for-byte.
Editing, transcoding or recompression can affect recovery.

</Details>

## Durable embedding and detection

- **Embed result:** native video bytes at `/watermarks/jobs/{request_id}/result`.
- **Detect result:** JSON at `/watermarks/detection-jobs/{request_id}/result`.
- **Per-frame results:** zero-based `units`. The top-level ID is present only when every frame recovers the same ID.
- **Retry:** keep the same upload and `Idempotency-Key`. A disconnect does not cancel work.

Follow `Retry-After` when polling. Jobs have a 30-minute deadline; completed
results last 24 hours. [Retry and recovery details](/docs/api/async#retry-safely).

## Credits

| Video length | CPU credits per operation |
| --- | --- |
| Up to 60 seconds | 1 |
| Over 60, up to 120 seconds | 2 |

Embedding and detection are charged separately. Credits are reserved on
acceptance, settled once on success and refunded on failure. Retries and saved
result downloads cost no extra credits. [GPU pricing](/docs/api/gpu#credits-and-fallback).

Python: `embed_video` / `detect_video`. Node.js: `embedVideo` / `detectVideo`.
Their result’s `image` field contains video bytes; save the returned filename and
content type. SDKs poll within their configured timeout.
