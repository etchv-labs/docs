<Endpoint method="POST" path="/watermarks/images/detect" />

Inspects an image and attempts to recover an embedded Etchv identifier.

## Request

Authenticate with `X-API-Key` and the `watermarks:detect` scope.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `file` | Image file | Yes | An encoded image, at most 20 MB and 40 megapixels |

```sh
curl --fail-with-body https://api.etchv.com/watermarks/images/detect \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -F 'file=@watermarked.png'
```

## Response

A successful request returns `200` with a JSON body and an `X-Request-ID` header.

| Field | Type | Description |
| --- | --- | --- |
| `watermarked` | Boolean | Whether the detector found a watermark |
| `confidence` | Number | Mean decoded-bit certainty, between 0 and 1 |
| `watermark_id` | String or null | Recovered 64-character hexadecimal ID, or null when no watermark is detected |

## Interpret the result

Compare `watermark_id` with the identifier stored when you embedded the image.
Confidence does not guarantee exact recovery after edits. The ID refers to your
record; the response does not contain the original JSON, a recipient's identity,
or proof of how the image was distributed.

An image without a detected watermark is still a successful detection request
and consumes a credit. Etchv does not determine whether an arbitrary unmarked
image was generated by AI.
