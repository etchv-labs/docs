## Request

Use a key with `watermarks:detect`. Send encoded image bytes as multipart `file`.

```sh
curl --fail-with-body https://api.etchv.com/watermarks/images/detect \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -F 'file=@watermarked.png'
```

## Response

Returns `200` JSON and an `X-Request-ID` header. Compare the recovered ID with
the one saved when you embedded the file.

| Field | Meaning |
| --- | --- |
| `watermarked` | Every frame/page/composite recovered the same watermark |
| `watermark_id` | Recovered 64-character hex ID, or `null` |
| `confidence` | Lowest per-unit decoded-bit certainty, from 0 to 1 |
| `units` | Per-unit `index`, `watermarked`, `confidence` and `watermark_id`; indexes start at zero |

## Interpret the result

- **Matching ID:** look up the associated record in your system.
- **Partial or mixed IDs:** inspect `units`. The top-level result is `watermarked: false` with a null ID.
- **No mark found:** a completed, billable detection. It does not establish whether an image is AI-generated.

Confidence is not a guarantee of exact recovery after edits. A match identifies
a copy, not who shared it. Detection does not return your original JSON or create
an asset-library record.

<Details title="Recovery from edited or photographed copies">

If a decoded ID is within 48 of 256 bits of an issued ID retained on one of your
organization’s watermarked assets, Etchv returns that issued ID. Only your
organization’s records are compared. Otherwise it returns the decoded ID, which
may match no record. Test the edits your workflow produces.

</Details>

## Choose sync or async

| Choice | How to request it |
| --- | --- |
| Synchronous | Use the endpoint above; returns detection JSON directly |
| Background job | Append `/async`; returns a `202` receipt. [Collect the result](/docs/api/async) |
| Completion event | Add `webhook_id` to an async request. [Webhooks](/docs/api/webhooks) |
| GPU | Add `accelerator=gpu`; Business/Enterprise, 3× credits when GPU runs. [GPU guide](/docs/api/gpu) |

Storage options are for embedding only. Large animations take longer because
every frame is inspected; a successful image detection still costs one CPU credit
for the whole file. [Image limits](/docs/api/errors#image-limits).
