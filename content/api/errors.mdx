Non-success responses normally contain JSON with a `detail` field. Save the
HTTP status and any `X-Request-ID` header when investigating a failed request.

## Status codes

| Status | Meaning | Next step |
| --- | --- | --- |
| `401` | Missing or invalid authentication | Check your API key |
| `402` | Billing or credits unavailable | Check the organization's plan and credit balance |
| `403` | Insufficient scope, membership, or plan access, including GPU processing below Business | Check [key permissions](/docs/authentication), [plan formats](/docs/billing) and [GPU processing](/docs/api/gpu) |
| `404` | Asset not found or outside your organization | Check the asset ID and organization |
| `409` | Conflicting input, duplicate operation or stale asset version | Inspect the operation, or reload the asset before editing |
| `410` | Job result or asset file expired/deleted | Check the asset library; records for expired files remain readable until deleted |
| `413` | File exceeds a size limit, or the request body exceeds 55 MB | Reduce the upload size or pixel dimensions |
| `415` | Recognized but unsupported file format, such as HEIC, HEIF or AVIF | Convert the file to a supported format, such as JPEG, PNG or WebP |
| `422` | Invalid input or failed watermark verification | Check image encoding and JSON data; try another source image if verification failed |
| `429` | Rate or concurrency limit reached | Wait for the `Retry-After` seconds, then retry. See [rate limits](#rate-limits) |
| `503` | A required service is unavailable | Check service status and handle the failure in your application |

## Rate limits

Every plan has two limits, applied per organization across all of its API keys and
the dashboard. See [limits by plan](/docs/billing#api-rate-limits).

- **Requests per minute** counts every authenticated API request, including job
  status checks, result downloads, asset requests and requests that are refused.
  The count resets at the start of each minute.
- **Concurrent operations** counts embedding and asynchronous detection jobs that are
  queued or running. Synchronous image and PDF detection count toward requests per
  minute only. Replaying an existing idempotency key is never rejected.

A request over either limit returns `429` without reserving credits. Its JSON
`detail` includes a `code` of `rate_limited` or `concurrency_limited` and the
`limit`, and the `Retry-After` header gives the seconds to wait. A
`concurrency_limited` response also includes `upgrade_url`, where you can move to a
plan that runs more operations at once; its `message` says so too.

```json
{
  "detail": {
    "message": "Your plan runs one operation at a time and one is already in progress. Wait for it to finish, or upgrade to run more operations in parallel (Business runs 16 at once): https://etchv.com/dashboard/billing",
    "code": "concurrency_limited",
    "limit": 1,
    "upgrade_url": "https://etchv.com/dashboard/billing"
  }
}
```

Responses for plans with a rate limit also carry:

| Header | Meaning |
| --- | --- |
| `X-RateLimit-Limit` | Requests allowed in the current minute |
| `X-RateLimit-Remaining` | Requests left in the current minute |
| `X-RateLimit-Reset` | Unix time, in seconds, when the current minute ends |

The SDKs retry `429` for embedding, video detection and job polling within the
client timeout; other calls return the error to your code. Poll job results no
faster than the `Retry-After` value on a `202` response (6 seconds on Trial and
Launch, 2 seconds on other plans), and prefer
[webhooks](/docs/api/webhooks) for long jobs. Enterprise plans have no rate
limit; [contact us](/contact) if you need more capacity on another plan.

## Image limits

| Limit | Maximum |
| --- | --- |
| API upload | 50 MB |
| Delivered file | 192 MB (lossless delivery can be larger than the upload: a 1-bit image is delivered with 8-bit color, and JPEG-compressed TIFF pages with lossless compression) |
| Dashboard upload | 20 MB (use the API for images up to 50 MB) |
| Detection upload | 95 MB, in the API and the dashboard: delivered files can be larger than uploads |
| Frames or pages per image | 32, including an APNG default/poster image |
| Total pixels across frames or pages | 40 megapixels |
| GIF frame | 1 megapixel |
| PSD/PSB canvas | 4 megapixels |
| PSD/PSB layers | 64 layers and 16 megapixels total, including the two added watermark layers |

HEIC, HEIF and AVIF photos are not supported yet and return `415` with the
format's name; convert them to JPEG, PNG or WebP first.

Send encoded image bytes, not a URL or base64 string. The `data` field must be a
non-empty JSON object. Embedding preserves the original format; high-bit-depth
and CMYK variants are unsupported. Files that browsers cannot preview can still
be uploaded through the dashboard.

See [PDF limits](/docs/api/documents#supported-files) and
[video limits](/docs/api/videos#supported-files) for other media.

## Credits and retries

Image and PDF operations each use one credit per file; video uses one credit per
started minute. Embedding reserves credits when its durable job is accepted,
charges once the verified result is saved, and releases the reservation on failure. Retries and result downloads do
not consume additional credits. During an outage, reservations remain until a worker
can complete or finalize the job.

Embedding SDK calls automatically retry transient failures and poll `202` jobs.
A client timeout does not cancel the job. Resume with the request ID or resubmit the
same image/data and idempotency key. Terminal JSON has `status: "failed"`; retrying
that key returns the same failure. See [embedding](/docs/api/embed) for retention.

The standard image and PDF detection endpoints are synchronous (their `/async` alternatives use durable jobs): SDKs do not retry those detections
automatically. Video detection uses durable jobs and automatic polling. Asset management and
downloads consume no credits.

## Service status

Check [status.etchv.com](https://status.etchv.com) for service availability.
For help, contact [hello@etchv.com](mailto:hello@etchv.com) with the request ID
and HTTP status. Do not send your API key.

Storage upload errors are recorded separately from watermarking errors. A failed
cloud upload does not invalidate an already verified Etchv asset or consume a
second credit. See [storage retry and error codes](/docs/storage).
