Browse, download and organize your files in the [asset library](/dashboard/assets). Every successful embed creates two linked records: the original upload and the watermarked result. Detection creates no assets.

<Facts>
  <Fact label="Files">30 days on Etchv</Fact>
  <Fact label="Records">Until you delete them</Fact>
  <Fact label="Credits">Free to manage</Fact>
</Facts>

## List assets

<Endpoint method="GET" path="/assets" />

```sh
curl --get https://api.etchv.com/assets \
  -H "X-API-Key: $ETCHV_API_KEY" \
  --data-urlencode 'kind=watermarked' \
  --data-urlencode 'media_type=image' \
  --data-urlencode 'limit=25'
```

| Query | Options |
| --- | --- |
| `limit` | 1–100; default `25` |
| `cursor` | Previous response’s `next_cursor` |
| `kind` | `source` or `watermarked`; omit for both |
| `media_type` | `image`, `document` or `video`; omit for all |
| `watermark_id` | Exact 64-character hexadecimal ID |

Returns `{ "items": [...], "next_cursor": "..." }`, newest first. Keep the same filters and organization between pages; stop when `next_cursor` is `null`. Listing omits metadata contents—read an individual record to retrieve them.

## Authentication

Send `X-API-Key` on every request, including downloads. Keys only access their organization’s assets.

| Scope | Access |
| --- | --- |
| `assets:read` | List, read and download |
| `assets:write` | Rename and replace metadata |
| `assets:delete` | Delete; requires an owner or admin |

Existing keys do not gain scopes automatically. Dashboard members can browse and edit; owners and admins can also delete.

## Read a record

<Endpoint method="GET" path="/assets/{asset_id}" />

```sh
curl "https://api.etchv.com/assets/$ASSET_ID" \
  -H "X-API-Key: $ETCHV_API_KEY"
```

| Field | Meaning |
| --- | --- |
| `id`, `name`, `version` | Stable ID, editable name and edit version |
| `kind`, `parent_asset_id` | Source or output; an output points to its source |
| `media_type`, `format`, `content_type` | Media category, format and MIME type |
| `size_bytes`, `sha256` | Stored file size and checksum |
| `request_id`, `watermark_id` | Creating job and embedded ID; sources have no added ID |
| `created_at`, `updated_at`, `file_expires_at` | UTC timestamps |
| `file_available`, `download_url` | Availability and authenticated download path |
| `metadata` | Your optional JSON record |

Set `include_metadata=false` to omit metadata. Unknown, deleted or foreign assets return `404`.

## Download a file

<Endpoint method="GET" path="/assets/{asset_id}/content" />

```sh
curl --fail-with-body "https://api.etchv.com/assets/$ASSET_ID/content" \
  -H "X-API-Key: $ETCHV_API_KEY" --output saved-file.png
```

Use your asset’s extension. The response preserves its MIME type and supplies an attachment filename. Keep the API key on your server; a download URL alone grants no access.

## Rename or update metadata

<Endpoint method="PATCH" path="/assets/{asset_id}" />

```sh
curl --request PATCH "https://api.etchv.com/assets/$ASSET_ID" \
  -H "X-API-Key: $ETCHV_API_KEY" -H 'Content-Type: application/json' \
  --data '{"version":1,"name":"Spring campaign","metadata":{"campaign":"spring","recipient":"partner-42"}}'
```

Send the current `version` and at least one of `name` or `metadata`. A successful edit increments the version. On `409`, reload the record and reconcile your changes.

<Callout title="Metadata replaces the existing object">
Send every field you want to keep. `{}` or `null` clears metadata. Editing a record never changes the file or watermark ID. The original embedding JSON is not saved automatically.
</Callout>

<Details title="Name and metadata limits">

| Field | Limit |
| --- | --- |
| Request body | 64 KB; unknown fields rejected |
| Name | 1–200 printable characters |
| Metadata | JSON object, 8 KB, up to eight nested levels |
| Metadata keys | 1–100 characters; no dots, null characters or leading `$` |
| Numbers | Finite; integers must fit signed 64-bit values |

</Details>

## Files and records

| Storage | Download window |
| --- | --- |
| Job result | 24 hours |
| Etchv-hosted asset | 30 days from completion |
| Customer bucket | Your bucket’s retention policy |
| Asset record | Until deleted, even after the file expires |

Embedding responses expose `X-Asset-ID` and `X-Source-Asset-ID`; job status exposes `asset_id` and `source_asset_id`. Replays create no extra assets or charges. Asset creation, job completion and credit settlement commit together.

<Details title="Customer storage and expired files">

After an Etchv file expires, `file_available` is `false` and `download_url` is `null`.

Customer-stored results include `storage_provider`, `storage_destination_id`, `storage_delivery_id` and `storage_status`. Once `stored`, `file_expires_at` is `null`; the asset download endpoint reads from your bucket. Access is checked on download, so a removed object or revoked connection can still fail.

`staging_expires_at` shows the upload recovery window; `staging_deleted_at` confirms Etchv’s staged output was removed. Failed delivery remains visible and retryable. Originals stay on Etchv for 30 days.

Connecting a bucket does not move existing files. Use **Move to my storage** on an available Etchv-hosted result. Each result has one destination. See [storage](/docs/storage).

</Details>

## Delete assets

<Endpoint method="DELETE" path="/assets/{asset_id}" />

```sh
curl --request DELETE "https://api.etchv.com/assets/$ASSET_ID" \
  -H "X-API-Key: $ETCHV_API_KEY"
```

For a batch, send 1–50 IDs to `POST /assets/bulk-delete`:

```json
{ "asset_ids": ["SOURCE_ASSET_ID", "OUTPUT_ASSET_ID"] }
```

Returns `204`. A batch succeeds entirely or makes no changes. Unknown or foreign IDs return `404`; repeating an owned deletion is safe.

<Details title="What deletion removes">

- New reads and downloads stop immediately. Background cleanup retries file removal; an in-progress download may finish.
- Source and output are independent: select both to delete both.
- Deleting an output also blocks its job result and idempotent replay with `410`, without another charge.
- Names and custom metadata are cleared. Minimal cleanup, job and billing records remain.
- Copies already downloaded elsewhere keep their watermarks. Etchv does not delete objects in your customer bucket.

</Details>
