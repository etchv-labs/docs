Each connector submits embedding or detection jobs, checks status, collects results and downloads saved assets.

## Before you connect

| Input | What to provide |
| --- | --- |
| API key | `watermarks:embed`, `watermarks:detect` and/or `assets:read`, saved in the platform’s credential store |
| File | Image, PDF or video; platform limits may be lower than [API limits](/docs/api/errors) |
| Reference data · embedding | Non-empty JSON, such as `{"asset":"142","delivery":"partner-a"}` |
| Idempotency key | Stable ID for one event and operation, such as `approved_asset_142_embed` |

Connection checks use no credits. Keep the original reference record: detection returns its watermark ID, not the JSON.

## What a workflow does

1. **Submit:** Save `request_id`, `status_url` and `result_url` from the receipt.
2. **Wait:** Check status about once a minute while `queued`, `running` or `retrying`.
3. **Collect:** On `succeeded`, download the file or read detection JSON.
4. **Handle failure:** On `failed`, record `request_id` and `error_code`; do not automatically create a new job.

Set a 35-minute workflow deadline; the job’s processing deadline is 30 minutes. Collect results within 24 hours, or use the [asset library](/docs/api/assets) for retained files.

<Callout title="Retry the same operation with the same key">
After a timeout, resend identical file, data and options with the original key. Etchv returns the same job without another reservation. Changed inputs return `409`.
</Callout>

A completed detection with `watermarked: false` still uses credits. See [billing](/docs/billing) and [job handling](/docs/api/async).
