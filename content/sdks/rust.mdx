Rust 1.88+. A blocking client; use a dedicated thread or `spawn_blocking` in async applications. MIT licensed.

## Install

```sh
cargo add etchv serde_json
```

Or add these dependencies to `Cargo.toml`:

```toml
[dependencies]
etchv = "1"
serde_json = "1"
```

## Embed a file

Set `ETCHV_API_KEY` on your server. This example needs `watermarks:embed`, an active plan and available credits.

```rust
use etchv::{Client, Options};
use serde_json::json;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::new(std::env::var("ETCHV_API_KEY")?)?;
    let key = client.get_api_key_info()?; // no credits used
    println!("Connected to {} with scopes {:?}", key.organization_id, key.scopes);

    let result = client.embed_image(&std::fs::read("photo.jpg")?,
        &json!({"asset": "photo-123"}), Options::new().filename("photo.jpg"))?;
    std::fs::write(&result.filename, &result.bytes)?;
    Ok(())
}
```

`get_api_key_info` checks credentials for free. Write output bytes without re-encoding.

## Images, documents and video

| Media | Embed / detect methods |
| --- | --- |
| [Images](/docs/api/embed) | `embed_image` / `detect_image` |
| [PDFs](/docs/api/documents) | `embed_document` / `detect_document` |
| [Videos](/docs/api/videos) | `embed_video` / `detect_video` |

Native output is in `result.bytes` for every media type. Embedding also returns `watermark_id`, `request_id`, `content_type`, `filename`, `asset_id`, `source_asset_id` and `storage_delivery_id`.

Detection returns the ID, confidence and per-frame/page results—not the original JSON. [Result fields](/docs/api/detect#response) · [Credits](/docs/billing#what-uses-credits).

<Details title="Client configuration">

`Client::with_options(key, base_url, Duration)` sets the base URL and timeout (default 120 seconds). Use `Options::new().filename(...).idempotency_key(...)` per media request. Later recipes assume an open client.

</Details>

## Retries and recovery

Embedding and video detection retry and poll automatically; image/PDF detection does not. Save an idempotency key before uploading to recover across restarts.

| Situation | Action |
| --- | --- |
| Client timeout | The accepted job continues; resume or resend identical inputs with the same key |
| Resume a job | `get_embed_result(request_id)` / `get_detection_result(request_id)` |
| Changed inputs | Use a new key; reusing one returns `409` |
| Collect a saved result | Within 24 hours; see [retention](/docs/api/assets#files-and-records) |

<Details title="Error types and handling">

Methods return `Result<T, etchv::Error>`. Inspect `kind` (`InvalidInput`, `Transport`, `Timeout`, `Api`, `InvalidResponse`), `status_code`, `message()`, `request_id` and `idempotency_key`. Status `0` means a client-side failure; `is_gone()` identifies HTTP 410.

```rust
match client.embed_document(&bytes, &serde_json::json!({"doc": "42"}), Options::new()) {
    Ok(result) => println!("{}", result.watermark_id),
    Err(e) if e.is_timeout() => eprintln!("retry with key {:?}", e.idempotency_key),
    Err(e) if e.kind == etchv::ErrorKind::Api => {
        eprintln!("HTTP {}, request {:?}", e.status_code, e.request_id)
    }
    Err(e) => eprintln!("{e}"),
}
```

See [HTTP errors](/docs/api/errors) and [retry behavior](/docs/api/async#retry-safely). Save the request ID when reporting failures.

</Details>

## Asset library

Scopes: `assets:read` for downloads, `assets:write` for edits, `assets:delete` plus owner/admin for deletion. No credits used.

<Details title="List, edit and download assets">

```rust
let page = client.list_assets(etchv::AssetListOptions::new().kind("watermarked").limit(25))?;
for item in page.items {
    let asset = client.get_asset(&item.id)?;
    let updated = client.update_asset(&asset.id, asset.version,
        &serde_json::json!({"metadata": {"campaign": "spring"}}))?;
    if updated.file_available {
        let bytes = client.download_asset(&updated.id)?;
    }
}
// Pass page.next_cursor to .cursor(...) with the same filters to continue listing.
```

Edits replace metadata and require the current version; reconcile `409` conflicts. `delete_asset` / `delete_assets` delete one asset or 1–50 atomically. [Asset fields, filters and retention](/docs/api/assets).

</Details>

## Async jobs and webhooks

Submit for a receipt without waiting: `submit_embed` / `submit_detection`; media: `Media::Image`, `Media::Document`, `Media::Video`.

`get_job` for embedding; `get_detection_job` for detection.

<Details title="Submit and collect an async job">

Load the media bytes before submitting.

```rust
use etchv::{JobStatus, Media, Options};

let job = client.submit_embed(Media::Document, &pdf_bytes,
    &serde_json::json!({"delivery": "delivery_001"}),
    Options::new().filename("document.pdf").idempotency_key("delivery_001"),
    Some(&webhook_id))?;
let status = client.get_job(&job.request_id)?;
if status.status == JobStatus::Succeeded {
    let result = client.get_embed_result(&job.request_id)?;
}
```

The webhook is optional (Java/Rust: pass `null` / `None`). Save the receipt. [Job handling](/docs/api/async).

</Details>

<Details title="Manage endpoints and verify webhooks">

Methods: `create_webhook`, `list_webhooks`, `update_webhook`, `delete_webhook`, `list_webhook_deliveries`, `redeliver_webhook`. Use `webhooks:read` to inspect or `webhooks:write` plus owner/admin to manage. Save the one-time signing secret.

```rust
// timestamp, signature and event_id are the X-Etchv-Timestamp,
// X-Etchv-Signature and X-Etchv-Event-ID header values.
if !etchv::verify_webhook_signature(&secret, timestamp, signature, raw_body) {
    return Err("invalid signature".into()); // respond 400
}
let event: etchv::WebhookEvent = serde_json::from_slice(raw_body)?;
if event.id != event_id {
    return Err("event ID mismatch".into());
}
// Deduplicate on event.id, enqueue work, then return 2xx.
```

`verify_webhook_signature` checks the signature and timestamp. Your handler must also compare the body ID with `X-Etchv-Event-ID`, as shown. Use raw bytes and a 300-second tolerance. Deduplicate, enqueue, then return `2xx`. [Verification rules](/docs/api/webhooks#verify-every-delivery).

</Details>

## GPU processing

Pass `Options::new().accelerator(Accelerator::Gpu)` on Business or Enterprise. GPU uses 3× credits; CPU fallback uses normal credits. `result.accelerator` reports the accelerator used. See
[GPU processing](/docs/api/gpu).

## Choose where results are stored

[Connect your bucket](/docs/storage), then pass its destination ID and optional object key. Omit both for Etchv storage.

<Details title="Deliver to your bucket">

```rust
let job = client.submit_embed(Media::Document, &pdf_bytes,
    &serde_json::json!({"recipient": "customer-123"}),
    Options::new()
        .filename("report.pdf")
        .idempotency_key("report-export-001")
        .storage_destination_id(&destination_id)
        .storage_key("reports/watermarked.pdf"),
    None)?;
// After the watermark job reports succeeded:
if let Some(id) = client.get_job(&job.request_id)?.storage_delivery_id {
    let delivery = client.get_storage_delivery(&id)?;
    println!("{}", delivery.status);
}
```

After job success, inspect delivery with `storage:read` (earlier reads return `404`). Once `stored`, use `download_storage_delivery` to download.

With `storage:write` and owner/admin access, `retry_storage_delivery` retries failed/cancelled delivery for free. Manage with: `NewStorageDestination::s3`, `gcs` or `azure`, then `create_storage_destination` and `verify_storage_destination`. Use `create_storage_delivery` to move an existing result. See [delivery recovery](/docs/storage#retry-retention-and-deletion).

</Details>
