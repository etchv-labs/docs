Watermark and asset API requests use an Etchv API key in the `X-API-Key` header.

```sh
curl https://api.etchv.com/watermarks/images/detect \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -F 'file=@watermarked.png'
```

## Create a key

Sign in to the [dashboard](/dashboard/api-keys), select your organization, and
create a key with the scopes your integration needs. Copy the key when it is
created and store it in your server's secret manager. You can also download its
details as a CSV on the confirmation screen; the full secret is unavailable after
you dismiss it.

| Scope | Allowed operation |
| --- | --- |
| `watermarks:embed` | Embed in an image, PDF or video |
| `watermarks:detect` | Detect in an image, PDF or video |
| `assets:read` | List, inspect and download assets |
| `assets:write` | Rename assets and replace metadata |
| `assets:delete` | Delete assets; also requires current owner or admin membership |
| `webhooks:read` | Inspect endpoints and deliveries |
| `webhooks:write` | Manage endpoints and redeliver events; owner or admin only |
| `storage:read` | Read destinations, inspect deliveries, and download exports |
| `storage:write` | Manage and verify connections, move results, and retry delivery; owner or admin only |

Keys belong to an organization and are subject to membership, expiration,
revocation, and billing checks. An authenticated key alone does not guarantee
that credits are available.

## Use keys in the dashboard

The watermarking and detection forms select an active key for your organization.
Use the API key dropdown to choose another; keys without the required permission
are disabled. Your choice is remembered for the current browser session.
Members can select their own keys; owners and admins can select organization keys.

Your signed-in session authorizes the selected key, so you do not need to paste
its secret into a form. The API checks scopes, expiry, revocation, and membership
on every request. Use Manage keys if you need to create a key.

The API request panel includes copyable examples for your selected media, request
mode, and storage destination. Set credentials on your server before running them.

## Keep credentials on your server

Do not embed keys in frontend JavaScript, mobile application bundles, public
repositories, or image URLs. Your backend should call Etchv on behalf of users.
Revoke a key immediately if it is exposed, then create a replacement.

## Authentication errors

A missing or invalid key returns `401`. A key without the required scope returns
`403`. Unavailable credits or billing can return `402`.

Automation connectors can check a key with `GET /auth/api-key`. Send the same
`X-API-Key` header; the response contains `organization_id`, `key_id`, and
`scopes`, with `Cache-Control: no-store`. This check requires an active key but
no particular media scope and consumes no credits. It does not authorize an
operation the key lacks permission to perform.

Account and organization management use signed-in account sessions. An image API
key is not a replacement for a user session on management endpoints.

Existing keys keep their scopes. Create a replacement key to add asset permissions.
Asset operations do not consume watermarking credits. See the [asset API](/docs/api/assets).

Submitting a job with a webhook or a verified storage destination uses the job’s
existing embed or detect scope. See [webhooks](/docs/api/webhooks) and
[storage setup](/docs/storage) for management details.
