Watermark and asset API requests use an Etchv API key in the `X-API-Key` header.

```sh
curl https://api.etchv.com/watermarks/images/detect \
  -H "X-API-Key: $ETCHV_API_KEY" \
  -F 'file=@watermarked.png'
```

## Create a key

Sign in to the [dashboard](/dashboard/api-keys), select your organization, and
create a key with the scopes your integration needs. Copy the key when it is
created and store it in your server's secret manager.

| Scope | Allowed operation |
| --- | --- |
| `watermarks:embed` | Embed in an image, PDF or video |
| `watermarks:detect` | Detect in an image, PDF or video |
| `assets:read` | List, inspect and download assets |
| `assets:write` | Rename assets and replace metadata |
| `assets:delete` | Delete assets; also requires current owner or admin membership |

Keys belong to an organization and are subject to membership, expiration,
revocation, and billing checks. An authenticated key alone does not guarantee
that credits are available.

## Use keys in the dashboard

When you create a key, copy it or use the download icon beside the key field to
save a CSV with its name, secret, permissions and dates. The full key is only
available on this confirmation screen; dismissing it removes the download option.

The watermarking and detection screens select an active key from your current
organization automatically. Open the **API key** dropdown in the toolbar to
search by name or prefix and choose another key. The selected name and active
status remain visible, and your choice is remembered for that organization in
this browser session. Resetting an operation keeps the selection.

You do not need to copy a secret into the dashboard. Your signed-in session
authorizes the selected key, and the API still checks its scopes, expiry,
revocation and organization membership for every request. Members can select
their own keys; owners and admins can select active keys in their organization.
Keys without the permission needed for the current operation are disabled.
If you have no active key, create one from **Manage keys**.

These controls work for images, PDFs and videos in both sync and async mode.
Server integrations and SDKs continue to use the `X-API-Key` header shown above.

## Keep credentials on your server

Do not embed keys in frontend JavaScript, mobile application bundles, public
repositories, or image URLs. Your backend should call Etchv on behalf of users.
Revoke a key immediately if it is exposed, then create a replacement.

## Authentication errors

A missing or invalid key returns `401`. A key without the required scope returns
`403`. Unavailable credits or billing can return `402`.

Account and organization management use signed-in account sessions. An image API
key is not a replacement for a user session on management endpoints.

Existing keys keep their scopes. Create a replacement key to add asset permissions.
Asset operations do not consume watermarking credits. See the [asset API](/docs/api/assets).

Webhook API access uses `webhooks:read` for endpoint and delivery inspection, and `webhooks:write` for endpoint management and redelivery. Management also requires an organization owner or admin. Submitting a job with a webhook only requires the job’s existing embed or detect scope.

Storage adds `storage:read` (read destinations/deliveries and download exported
objects) and `storage:write` (owner/admin connection management, verification,
exports and retries). Existing `watermarks:embed` keys can select a verified
destination in their organization. [Storage setup](/docs/storage).
