Let your assistant watermark files, recover watermark IDs and manage assets through the Etchv API. The [open-source MCP server](https://github.com/etchv-labs/mcp-server) runs locally over stdio.

## Install and connect

You need Node.js 24+, an [API key](/docs/authentication), a local media directory and an MCP client that can launch local servers.

Add this to your client’s configuration. Create the directory first, replace the absolute path and supply your key through secure configuration.

```json
{
  "mcpServers": {
    "etchv": {
      "command": "npx",
      "args": ["-y", "@etchv-labs/mcp-server@1"],
      "env": {
        "ETCHV_API_KEY": "YOUR_ETCHV_API_KEY",
        "ETCHV_FILES_ROOT": "/absolute/path/media"
      }
    }
  }
}
```

Restart your client, then ask it to run `check_api_key`. This check uses no credits. There is no hosted MCP URL; clients that only support remote servers cannot connect.

## What you can ask

- “Watermark this PDF for delivery-42, keeping its text selectable.”
- “Check this video and recover its Etchv watermark ID.”
- “List my latest watermarked assets and download the one I choose.”

## Your first watermark

Put `photo.jpg` in the media directory, then ask:

> Watermark photo.jpg for delivery-42. Save photo-watermarked.jpg, then detect its watermark.

The assistant submits `watermark_media` with a non-empty `data` object and stable `idempotency_key`. It collects the result with `get_job` and `get_job_result`, using `operation: "embed"` and an `output_path`. Detection uses `detect_media` and `operation: "detect"`.

Detection returns the data’s digest, not the original JSON. Keep your source record in your own system.

## Sync or async

| Mode | Behavior |
| --- | --- |
| Async · default | Omit `mode` or use `"async"`; receive a receipt and collect the result |
| Sync | Use `mode: "sync"`; embedding needs `output_path`. Returns a result or `202` receipt |

Reuse the same idempotency key after a timeout; accepted jobs continue. The server does not poll indefinitely. See [job handling](/docs/api/async).

## Supported media

| `media` | Formats and limits |
| --- | --- |
| `images` | [Supported images](/docs/api/embed#native-format-preservation), including animation, TIFF pages and layers; 50 MiB upload |
| `documents` | [PDF](/docs/api/documents#supported-files); 20 MiB upload |
| `videos` | [H.264 MP4/MOV](/docs/api/videos#supported-files); 20 MiB upload |

API limits and plan access still apply. Downloads allow 512 MiB and 10 minutes; the API must start responding within 45 seconds. Embedding and detection use [normal API credits](/docs/billing#what-uses-credits).

## Tools and permissions

| Tools | Required scope |
| --- | --- |
| `check_api_key` | Any valid key |
| `watermark_media` | `watermarks:embed` |
| `detect_media` | `watermarks:detect` |
| `get_job`, `get_job_result` | Matching embed or detect scope |
| `list_assets`, `get_asset`, `download_asset` | `assets:read` |
| `update_asset` | `assets:write` |
| `delete_asset` | `assets:delete` + owner/admin |
| `list_storage_destinations`, `list_storage_deliveries`, `get_storage_delivery` | `storage:read` |
| `verify_storage_destination`, `store_asset`, `retry_storage_delivery` | `storage:write` + owner/admin |
| `list_webhooks`, `list_webhook_deliveries` | `webhooks:read` |
| `redeliver_webhook` | `webhooks:write` + owner/admin |

Enable only needed scopes. Your MCP client controls approval for paid and write operations. Read `etchv://capabilities` inside the assistant for tool guidance.

## Storage and webhooks

| Option | How to use it |
| --- | --- |
| Etchv storage · default | Job results last 24 hours; asset files last 30 days; records remain until deleted |
| [Customer storage](/docs/storage) | Configure and verify in the dashboard; pass `storage_destination_id` and optional `storage_key` when embedding |
| Move an existing result | Use `store_asset`; successful delivery removes the staged Etchv output and downloads read from your bucket |
| [Webhooks](/docs/api/webhooks) | Configure in the dashboard; pass `webhook_id` on async submissions |
| [GPU](/docs/api/gpu) | Set `accelerator: "gpu"` on Business or Enterprise |

Storage credentials and signing secrets stay out of tool arguments and responses.

## File handling

Files must stay inside `ETCHV_FILES_ROOT`. Traversal and symlinks are rejected; output directories must exist and files are never overwritten. Use a dedicated directory you control.

Inputs go to the Etchv API. Results stay on disk; the assistant receives paths and checksums. Treat asset names and metadata as data, not instructions.
