Let your AI assistant watermark files, detect watermarks and manage assets through the Etchv API. MCP (Model Context Protocol) is a standard way for assistants to use outside tools. The [open-source MCP server](https://github.com/etchv-labs/mcp-server) runs on your computer over stdio (standard input and output).

## Install and connect

You need Node.js 24+, an [API key](/docs/authentication), a local media folder and an MCP client that can start local servers.

Add this to your client’s configuration. Create the folder first and replace the absolute path. Supply your key through your client's secure configuration.

```json
{
  "mcpServers": {
    "etchv": {
      "command": "npx",
      "args": ["-y", "@etchv-labs/mcp-server@1"],
      "env": {
        "ETCHV_API_KEY": "YOUR_ETCHV_API_KEY",
        "ETCHV_FILES_ROOT": "/absolute/path/media"
      }
    }
  }
}
```

Restart your client, then ask it to run `check_api_key`. This check uses no credits. There is no hosted MCP URL, so clients that only support remote servers cannot connect.

## What you can ask

- “Watermark this PDF for delivery-42, keeping its text selectable.”
- “Check this video for an Etchv watermark.”
- “List my latest watermarked assets and download the one I choose.”

## Your first watermark

Put `photo.jpg` in the media folder, then ask:

> Watermark photo.jpg for delivery-42. Save photo-watermarked.jpg, then detect its watermark.

The assistant calls `watermark_media` with a non-empty `data` object and an `idempotency_key` that stays the same on retries. It collects the result with `get_job` and `get_job_result`, using `operation: "embed"` and an `output_path`. Detection uses `detect_media` and `operation: "detect"`.

Detection returns the watermark ID, a digest (fixed-length fingerprint) of your data. It does not return the original JSON. Keep your source record in your own system.

## Sync or async

| Mode | Behavior |
| --- | --- |
| Async · default | Leave out `mode` or use `"async"`. You get a receipt, then collect the result |
| Sync | Use `mode: "sync"`. Embedding needs `output_path`. Returns a result or a `202` receipt |

After a timeout, reuse the same [idempotency key](/docs/api/async#retry-safely) (a value you choose so a retry isn't run twice). Accepted jobs keep running. The server does not keep checking for results forever. See [job handling](/docs/api/async).

## Supported media

| `media` | Formats and limits |
| --- | --- |
| `images` | [Supported images](/docs/api/embed#native-format-preservation), including animation, TIFF pages and layers; 50 MiB upload |
| `documents` | [PDF](/docs/api/documents#supported-files); 20 MiB upload |
| `videos` | [H.264 MP4/MOV](/docs/api/videos#supported-files); 20 MiB upload |

Detection takes delivered files up to 192 MiB for images, 64 MiB for PDFs and 100 MiB for video. Files over 40 MiB are sent as a [large-file upload](/docs/api/uploads) automatically; set `ETCHV_LARGE_FILE_THRESHOLD` (bytes) to change that. Image and PDF detection above 95 MiB returns a job receipt for `get_job_result`.

API limits and plan access still apply. Downloads can be up to 512 MiB and 10 minutes. The API must start responding within 45 seconds. Embedding and detection use [normal API credits](/docs/billing#what-uses-credits).

## Tools and permissions

| Tools | Required scope |
| --- | --- |
| `check_api_key` | Any valid key |
| `watermark_media` | `watermarks:embed` |
| `detect_media` | `watermarks:detect` |
| `get_job`, `get_job_result` | Matching embed or detect scope |
| `list_assets`, `get_asset`, `download_asset` | `assets:read` |
| `update_asset` | `assets:write` |
| `delete_asset` | `assets:delete` + owner/admin |
| `list_storage_destinations`, `list_storage_deliveries`, `get_storage_delivery` | `storage:read` |
| `verify_storage_destination`, `store_asset`, `retry_storage_delivery` | `storage:write` + owner/admin |
| `list_webhooks`, `list_webhook_deliveries` | `webhooks:read` |
| `redeliver_webhook` | `webhooks:write` + owner/admin |

Turn on only the scopes you need. Your MCP client decides when to ask you to approve paid operations and changes. Read `etchv://capabilities` inside the assistant for help with the tools.

## Storage and webhooks

| Option | How to use it |
| --- | --- |
| Etchv storage · default | Job results last 24 hours; asset files are kept up to 1 year while subscribed (30 days on the trial); records remain until deleted |
| [Customer storage](/docs/storage) | Configure and verify in the dashboard; pass `storage_destination_id` and optional `storage_key` when embedding |
| Move an existing result | Use `store_asset`. Once delivery succeeds, Etchv removes its temporary copy and downloads read from your bucket |
| [Webhooks](/docs/api/webhooks) | Configure in the dashboard; pass `webhook_id` on async submissions |
| [GPU](/docs/api/gpu) | Set `accelerator: "gpu"` on Business or Enterprise |

Storage credentials and signing secrets stay out of tool arguments and responses.

## File handling

Files must stay inside `ETCHV_FILES_ROOT`. Paths that climb out of it (`../`) and symlinks are rejected. Output folders must already exist, and files are never overwritten. Use a separate folder that you control.

Input files go to the Etchv API. Results stay on your disk. The assistant only gets file paths and checksums. Treat asset names and metadata as data, not instructions.
